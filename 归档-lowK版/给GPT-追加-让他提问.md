# 追加指令：看不清的地方直接列问题问用户

> 附在上一条任务后面一起发给 GPT。用户会回答，然后你再继续。

## 规则

1. **凡是你在下面两类情况里拿不准的，不要猜、也不要硬给结论 —— 编号列成问题。**
   - 从作者文档那 5 张天赋树截图里**看不清**的地方（图只有 1500px 宽，节点图标约 3~4 像素，
     只能看见发光的点团、看不出是哪个节点 —— 这是实测结论，别指望靠视觉硬认）
   - **只有用户知道**的事实（作者的等级、他当时身上的装备、有没有用双天赋、视频里说了什么）

2. **一次问完，编号列出，不要分多轮。** 每个问题要写清：
   - 你为什么要问它（它会影响哪个决定）
   - 你希望用户回答什么形式（是/否、数字、名字、还是"看不清"）

3. 用户回答后，**明确写出**：哪几条结论因为用户回答而改变、哪几条维持原样。
   如果回答不足以下结论，就说还缺什么。

## 建议优先问这几类（按对结论的影响排序）

### A. 决定点数预算
1. 作者第一天打完 T15 时是**几级**？（这决定第一天该是 93 点还是别的数字）
2. 第一天他**任务天赋点**领齐了吗（间章那 24 点）？

### B. 决定「有前提的取舍」是否保留
3. 第一天他身上已经有哪几件关键装备？
   （穿抗手 / 寒焰头 / 猎心弓 / 卡迪罗的赌局箭袋 / 带珠宝的珠宝孔）
   —— 珠宝孔、`evasion_and_energy_shield*`、`evasion33` 这些点值不值得留，取决于装备
4. 他第一天有没有用**双天赋**（主天赋 + 副天赋）？

### C. 唯一可能验证「是不是作者原树」的问题
5. 你（或用户）看作者那 5 张天赋树截图时，**能不能看清任何节点的名字/图标**？
   - 能 → 把能看清的大点名字列出来，用户会核对是否与树一致
   - 不能 → 直接说明「截图不足以验证」，不要编

### D. 机制细节（影响节点取舍）
6. 弹幕消耗的是**狂怒球**（第一天靠战斗狂怒获取）还是别的？确认后再判断相关节点
7. 冰冻印记挂上后是**一直有效**还是被消耗后就没了？（这影响 `marks12`、`marks27` 的价值）

## 输出格式

```
【我需要用户确认的问题】

Q1. ...（为什么问：... / 希望回答：...）
Q2. ...

—— 收到回答后我会：① 重新核对 __ 项；② 明确写出哪些结论改变。
```

如果一个问题都不需要问，就直接写「不需要额外信息」，并给出最终结论。
